# M0: Green build and hygiene

- Built: lint, type-check, tests and build all pass with 0 warnings; the Spotify secret is scrubbed from the root commit before any push; the 3 type errors, the `as any`, and the `console`/`alert` calls are gone (pino logger plus in-page error states); husky + lint-staged gate every commit.
- Measured: First Load JS baseline in `docs/metrics/perf-baseline.txt` (`/` is 136 kB, mostly framer-motion; that is the target for M5).
- Trade-off 1: stayed on Next 14 and renamed `next.config.ts` to `.mjs` instead of upgrading to Next 15 (which supports TS config and flat ESLint). A major upgrade changes caching and the async `cookies()` API right before the auth rework, so it is a separate decision, not a side effect of fixing the build.
- Trade-off 2: the pre-commit hook runs `tsc --noEmit` on the whole project, not just staged files. It's slower per commit, but type errors are cross-file: changing a type in `types/index.ts` can break a file you didn't touch, and only a whole-project check catches that.
- Still manual: rotate the Spotify client secret in the Spotify dashboard (the old one was in a local commit).
