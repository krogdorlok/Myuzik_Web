# M7: Deploy and present

- Built: a Railway config (Dockerfile, `/health` healthcheck, one replica); `scripts/smoke.sh`, which checks liveness and the security posture (CSP, proxy allow-list, CSRF, auth, WebSocket ticket); a README with a demo GIF, an architecture diagram and a metrics table generated from `docs/metrics/*.json` (`node scripts/metrics-table.mjs`).
- Trade-off 1: a single backend replica. The model and the live-session and ticket maps live in process memory. Scaling out means moving tickets and sessions to Redis and using sticky WebSocket routing. Until then, one well-used process is simpler and honest.
- Trade-off 2: VGGish ships as a checksum-pinned GitHub release asset rather than through Git LFS or a model registry. TF Hub no longer serves it, release assets have no bandwidth quota, and `ADD --checksum` means a tampered file fails the build.
- Still manual: creating the GitHub repo and the release asset, and connecting Vercel and Railway (all need account access).
