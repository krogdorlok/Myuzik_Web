# M1: Real model behind the API

- Built: the random placeholder is replaced by the real VGGish + logistic-regression classifier. It loads once in `lifespan`, inference runs in a threadpool behind a lock, and there are 32 backend tests (auth, upload validation, history ownership, insights, mocked Spotify, real model).
- Measured: 84.8% accuracy and 0.844 macro-F1 on the 197-clip held-out GTZAN split (`docs/metrics/model.json`), measured on the production path. That replaces the README's unverified "~88%". The split is random, not artist-filtered, so treat it as an optimistic estimate.
- Trade-off 1: VGGish runs as a LiteRT flatbuffer instead of TensorFlow. TF Hub no longer serves the model, and TF is a 1.1 GB package. LiteRT embeddings match TF to 6.6e-6, the 2.88 s live window runs in 14.8 ms instead of 33 ms (`docs/metrics/model-export.json`), and the server venv is 136 MB in total. The cost is that the 289 MB model must be shipped as a checksum-pinned GitHub release asset.
- Trade-off 2: the scikit-learn pickle became plain NumPy weights (`classifier.npz`, loaded with `allow_pickle=False`). Unpickling runs arbitrary code, and softmax(Wx+b) reproduces `predict_proba` exactly (max difference 0.0), so scikit-learn is gone from the server too. The catch: retraining now requires re-running `scripts/export_model.py`.
- Gotcha worth knowing: a single 0.96 s chunk yields zero VGGish embeddings (the 25 ms STFT window needs 240 more samples), so live mode must buffer at least 2 chunks.
