# M5: Performance

- Built: First Load JS for `/` went from 136 kB to 107 kB. `import "server-only"` makes the build fail if server code leaks into a client bundle. Web Vitals are beaconed to `/api/vitals`. `npm run perf` enforces Lighthouse mobile budgets (performance ≥ 90, accessibility = 100) and records the numbers (`docs/metrics/perf.json`).
- Found: `/sign-in` failed Lighthouse with NO_FCP because the entire page faded in from opacity 0, and Chrome doesn't count invisible content as painted. The logo now paints immediately and only the form animates.
- Trade-off 1: I deleted heavy libraries rather than lazy-loading them. Code-splitting recharts would have saved bytes on the first page but still cost them on Insights, while removing it saved them everywhere.
- Trade-off 2: the budgets run against a local production build with Lighthouse's simulated mobile throttling. That's reproducible and runs in CI, but it isn't field data. The Web Vitals beacon exists so that real-user LCP, CLS and INP can confirm it.
- Defend: about 87 kB of every page is the shared React/Next runtime. Per-route JS is 3–14 kB, and Live is the largest because of the zod schema and the socket state machine.
