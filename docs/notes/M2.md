# M2: Auth and upload security

- Built: `/api/auth/{login,register,logout}` set the JWT as an httpOnly, SameSite=Lax cookie. The proxy uses route and header allow-lists, has a 30 s timeout and rejects cross-origin writes. Middleware adds a per-request nonce CSP and redirects signed-out users. `?next=` is resolved against our own origin. Uploads are checked by magic bytes, type and size on both sides, and the server rejects bodies before parsing multipart.
- Found by review and fixed: `auth%2Flogin` slipped past a block-list (now an allow-list); login CSRF through a cross-site `text/plain` form; an open redirect via `/\evil`.
- Trade-off 1: the token lives in a cookie set by the server, and the browser talks to a same-origin proxy rather than to FastAPI directly. JS can't read an httpOnly cookie, so XSS can't steal the session. The cost is one extra hop per request, and the proxy has to be hardened, since it's now an attack surface.
- Trade-off 2: a nonce-based CSP rather than `'unsafe-inline'`. It forces every page to render dynamically, because a nonce exists per request, so there's no static HTML caching. These pages are per-user behind auth anyway, so that costs almost nothing here.
- Defend: SameSite=Lax keeps the cookie off cross-site POSTs, but a form can still *set* a session (login CSRF). That's why auth routes also require same-origin JSON.
