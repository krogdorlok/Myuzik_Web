# M6: Tests and CI

- Built: 93 Vitest/RTL tests covering every component, hook and client library, gated at 85% line and branch coverage (currently about 99% and 94%). Playwright covers auth and security, upload, history, insights, Live Listen (file mode, Chromium fake mic, and a scripted disconnect and resume through `routeWebSocket`) and axe, across 5 projects. Backend pytest covers the API and the WebSocket limits. GitHub Actions runs all of it, plus the Lighthouse budgets, against real Postgres and the real model.
- Bugs the tests caught: a failed delete's error was wiped by the refetch that followed it, and a `stop()` issued during `start()`'s teardown was overtaken by that same start.
- Trade-off 1: I mock at the `@/lib/api` module boundary rather than adding MSW. There's one less dependency, and the request layer itself is unit-tested separately with stubbed fetch and XHR.
- Trade-off 2: the Web Audio graph (`liveAudio.ts`) is left out of unit coverage and covered only by Playwright in real browsers, because jsdom has no audio engine. Faking one would test the fake.
- Note: on this macOS 26 machine, Playwright's WebKit build segfaults on launch. Chromium, Firefox and Mobile Chrome pass locally; WebKit and Mobile Safari are verified in CI on Ubuntu.
