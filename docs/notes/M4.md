# M4: Complete, responsive, accessible UI

- Built: DropZone (a real file input, so it works from the keyboard), XHR upload progress with cancel, ResultCard with labelled progressbars, paged and filterable history with race-safe deletes, a dependency-free SVG donut, skeleton, empty and error states everywhere, and layouts from 360 px up.
- Found while testing: Tailwind had never compiled (no PostCSS config), fonts never loaded (`"Syne"` instead of the `next/font` CSS variable), and muted text was at 3.4:1 contrast. All fixed; axe now reports 0 violations at desktop and mobile widths.
- Trade-off 1: XHR rather than fetch for uploads, because XHR is the only browser API that reports upload progress. In exchange I own abort handling and error mapping by hand.
- Trade-off 2: I removed framer-motion, recharts and zustand. CSS keyframes cover the motion spec, the donut is about 40 lines of SVG, and no state needed to be global. That's less JS on every page, with the caveat that I don't get spring physics.
- Defend: the delete confirmation moves focus into itself and back out again; announcements go through `role=alert`; inline links are underlined, because color alone isn't enough to tell them apart.
